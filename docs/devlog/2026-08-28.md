# Devlog — 28 Agustus 2026

## 1. Sumber Data CT Log: Keputusan `ctlogs.dev` & Evaluasi `crt.sh`

Pada pengujian awal collector (T03), kami melakukan request nyata ke endpoint `crt.sh` (`https://crt.sh/?q=%.id&output=json` dan variasi wildcard lainnya).
- **Temuan:** `crt.sh` mengembalikan error **HTTP 502 (Bad Gateway)** secara konsisten pada seluruh query wildcard TLD maupun keyword lebar (`%.co.id`, `%.web.id`, `%bank%`). Hal ini disebabkan beban database PostgreSQL `crt.sh` yang kelebihan muatan untuk pencarian wildcard skala besar.
- **Solusi:** Kami menguji dan memverifikasi endpoint REST API `ctlogs.dev` (`https://api.ctlogs.dev/v1/subdomains/{tld}`). `ctlogs.dev` terbukti sangat cepat, stabil, dan mengembalikan sertifikat terurut waktu terbaru dengan dukungan pagination kursor.
- **Keputusan:** `ctlogs.dev` ditetapkan sebagai sumber data primer untuk Aliran A (`.id` family), sedangkan `crt.sh` diturunkan sebagai slot cadangan (*fallback*).

## 2. Temuan Timestamp `not_before` yang Sempat Terbuang

- **Masalah:** Pada implementasi awal collector, `not_before` (waktu penerbitan sertifikat dari payload CT log) hanya dibaca untuk menentukan batas waktu cutoff 24 jam, lalu dibuang. Data yang disimpan ke `ct_raw` hanya kolom `first_seen` yang diisi timestamp saat script collector dijalankan.
- **Dampak Teknis:** Jika hanya mengandalkan `first_seen`, metrik headline *"rata-rata umur domain saat terdeteksi"* (`first_seen − registered_at`) akan mengalami bias / distorsi keterlambatan jadwal cron (antara 0–24 jam, rata-rata ~12 jam). Hal ini membuat deteksi SIAGA tampak lebih lambat dari performa aslinya.
- **Perbaikan:** Skema `ct_raw` diperluas dengan menambahkan kolom `not_before TIMESTAMP`. Parser `ct_collector.py` diperbarui untuk menyimpan timestamp `not_before` asli dari sertifikat ke database SQLite. Dengan demikian, metrik lead time dan umur domain dihitung secara presisi dari `not_before − registered_at`, serta memungkinkan pengukuran **detection lag (pipeline delay)** melalui `first_seen − not_before`.
