# Devlog 02 September 2026 — Perbaikan Infrastruktur, Onboarding Agent, Aliran B

## Ringkasan

Sesi ini dimulai dari audit ulang status VPS setelah sesi sebelumnya menyimpang ke deployment
Vercel yang tidak diminta. Ditemukan bahwa Batch VPS lomba (Batch 1: 1-5 September 2026) hanya
memberi jendela 5 hari sebelum VM dinonaktifkan panitia — jauh lebih pendek dari asumsi awal
proyek (VPS aktif sepanjang periode lomba). Ini mengubah prioritas: footage video harus direkam
sebelum 5 September, dan collector lokal (bukan VPS) tetap jadi sumber data jangka panjang utama.

---

## 1. OpenClaw Gateway crash-loop (T11) — ditemukan dan diperbaiki

Gateway di VPS ternyata restart tanpa henti setiap ~10-20 detik sejak dipasang (restart counter
2280+ saat ditemukan). Akibatnya channel Telegram (Mode A / perintah interaktif) mati total —
`[telegram] channel autostart suppressed by crash-loop breaker`.

**Root cause** (ditemukan lewat `openclaw doctor`, bukan tebakan — sesuai aturan CLAUDE.md):
`OPENCLAW_SERVICE_REPAIR_POLICY=external` tidak diset di systemd unit, sehingga logika
self-respawn internal OpenClaw bentrok dengan `Restart=always` milik systemd.

**Perbaikan:** tambah env var tersebut ke `/etc/systemd/system/openclaw-gateway.service`,
restart, verifikasi `NRestarts=0` stabil, lalu `openclaw gateway call channels.start` untuk
memulihkan channel Telegram secara manual (breaker masih menahan autostart selama window 5 menit
setelah crash terakhir). Sekaligus set `commands.ownerAllowFrom` sesuai rekomendasi doctor.

## 2. Insiden: token Telegram sempat tercetak ke transkrip sesi

Saat men-diff `openclaw.json` untuk mencari akar masalah, token bot Telegram sempat tampil utuh
di output sebelum disensor pada percobaan berikutnya. Pengguna memutuskan **tidak merotasi**
token tersebut (keputusan eksplisit pengguna, bukan rekomendasi default). Dicatat di sini sebagai
bagian dari catatan kejujuran proyek, bukan disembunyikan.

## 3. OpenClaw workspace belum pernah di-onboarding

Ditemukan `IDENTITY.md` masih placeholder kosong, `BOOTSTRAP.md` belum dihapus (seharusnya
dihapus setelah first-run), nol penyebutan "siaga/phishing/fraud" di seluruh workspace agent.
Bot yang berjalan adalah asisten OpenClaw generik tanpa identitas proyek — signifikan karena
kategori lomba ini secara eksplisit menilai "penggunaan fitur AI hosting" (bobot 20%).

**Perbaikan:** `IDENTITY.md` (nama: SIAGA), `USER.md` (konteks proyek & pengguna), dan section
"Misi SIAGA" ditambahkan ke `AGENTS.md` (batasan keras: selalu "indikasi" bukan "terbukti", tidak
pernah mengarang angka, tidak eksekusi apa pun ke domain yang diperiksa). `TOOLS.md` diberi catatan
lingkungan (path repo, DB, catatan bahwa exec ke repo SIAGA belum diverifikasi end-to-end).

## 4. VPS crontab tidak menjalankan pipeline — cuma collector mentah

`run_daily_cycle.py` (pipeline + campaign clustering + brief Telegram) ada di repo VPS tapi
**tidak pernah masuk crontab**. Hanya collector mentah, healthcheck, dan backup yang terjadwal.
`domain_findings` di VPS berisi 548 baris — hasil satu kali jalan manual (saat migrasi T10),
bukan proses harian berkelanjutan. Ditambahkan entri cron baru: `45 6 * * *` (15 menit setelah
collector), belum diverifikasi lewat siklus otomatis penuh — cek besok pagi.

## 5. Aliran B — rancangan awal terbukti tidak bisa dibangun, dipivot

CLAUDE.md dan `plan/` sejak awal menyatakan Aliran B (TLD global: `.xyz`, `.top`, `.online`, dll)
wajib ada karena penipu nyata jarang pakai `.co.id` (butuh dokumen legal). Belum pernah dibangun
sampai sesi ini. Tiga jalur diverifikasi lewat request nyata (bukan tebakan):

| Jalur | Hasil |
|---|---|
| `ctlogs.dev` endpoint TLD-wide | **Tidak ada.** Hanya exact-domain, subdomains-of-a-domain, org search, serial, SPKI. Bare TLD (`xyz`) ditolak validasi hostname. |
| `crt.sh` JSON API (`?q=%25brand%25`) | 502 Bad Gateway konsisten (3x percobaan) |
| `crt.sh` Postgres publik (`guest@crt.sh:5432`) | Konek berhasil, tapi query timeout/putus tidak menentu |
| CertStream firehose | Layanan publik gratis (`certstream.calidog.io`) sudah mati; pengganti (`certstream.dev`) cuma software self-host, butuh server nyala 24/7 |

**Kesimpulan:** tidak ada layanan gratis untuk "pantau semua sertifikat baru di TLD X" secara
andal. Desain awal di `plan/` tidak realistis dengan constraint jaringan proyek ini.

**Pivot (diimplementasikan, `collector/ct_collector_b.py`):** generate kandidat typosquat dari
214 stem watchlist (exact + 6 modifier umpan phishing x 2 TLD murah = 2.688 kandidat), cek satu
per satu ke endpoint `/v1/domain/{hostname}` yang TERBUKTI berfungsi (exact-domain lookup). Mirip
teknik dnstwist. Match pertama yang ditemukan saat uji: `adakami.xyz` (official domain AdaKami
sebenarnya `adakami.id`) — sertifikat sejak Juli 2025, layak diperiksa Tahap 2/3.

**Bug ditemukan & diperbaiki di percobaan pertama:** HTTP 429 (rate limit) tidak ditangani,
membuat seluruh run mati dalam <1 menit dengan 0 hasil dari 2.688 kandidat, bukan diperlakukan
sebagai error per-kandidat. Diperbaiki dengan exception `RateLimited` terpisah, backoff+retry
per kandidat, dan penghentian dini kalau server terus menolak beruntun (bukan menggerus ribuan
kandidat yang pasti gagal semua). 17 test baru di `tests/test_ct_collector_b.py`, termasuk
regression test spesifik untuk bug 429 ini.

## Legacy / catatan untuk sesi berikutnya

- Verifikasi cron `run_daily_cycle.py` di VPS besok pagi (06:45 WIB) — belum pernah tervalidasi
  lewat siklus otomatis.
- Tool-wiring penuh Mode A (`/laporkan` -> `scripts/draft_report.py` via exec agent) masih belum
  diverifikasi ujung-ke-ujung — sengaja dicatat jujur di `AGENTS.md` sebagai "masih pengembangan"
  daripada mengklaim sudah bisa padahal belum diuji.
- Task Scheduler Windows lokal masih `LogonType: Interactive` (root cause uptime collector 75%)
  — perbaikan butuh PowerShell elevated, belum dikonfirmasi dijalankan pengguna.
